# 깨지면 안 되는 것들

새 기능을 붙일 때마다 이 목록을 다시 통과해야 한다. 각 항목은 한 번씩 실제로 깨진 적이 있는 것이고, 무엇이 잘못되는지를 적어 둔다.

## 화면

| 이름 | 깨지면 안 되는 것 | 깨지면 무엇이 잘못되나 |
|---|---|---|
| 강조와 배지 일치 | 행동형 배지(답장 필요, 처리 필요, 승인 대기, 일정)가 붙은 행은 반드시 강조된다. 강조되지 않은 행에는 행동형 배지가 붙지 않는다 | 같은 배지가 어떤 행에서는 강조되고 어떤 행에서는 아니게 되어, 화면만 보는 사람에게 규칙이 없는 것으로 읽힌다 |
| 숫자와 화면 일치 | 패널이 말하는 건수와 화면에서 강조된 행의 수가 같다 | 숫자를 믿을 수 없게 된다. 내부적으로 두 질문을 쓰면 서로 다른 것을 세기 쉽다 |
| 섞임에는 이유가 있다 | 표시가 있는 행과 없는 행이 섞이면 그 이유가 패널에 적힌다 | 확인할 것이 없다면서 어떤 행만 흐린 화면이 된다 |
| 지움은 유지된다 | 표시를 지운 뒤에는 어떤 경로로도 다시 그리지 않는다 | 목록 재생성 복원이 사용자가 지운 것과 서비스가 다시 그린 것을 구별하지 못해, 지우자마자 되살아난다 |
| 문구는 사실을 넘지 않는다 | 화면 문구는 확장이 확인한 것보다 강하게 말하지 않는다 | 읽기만 하고 답장하지 않은 메일에 처리했다고 적히는 식으로, 확장이 알 수 없는 것을 단정하게 된다 |
| 숫자는 접어도 보인다 | 접은 상태에서도 남은 건수가 화면에 있다 | 처리해도 줄어드는 것이 보이지 않아 기능이 동작하지 않는 것처럼 읽힌다 |

## 상호작용

| 이름 | 깨지면 안 되는 것 | 깨지면 무엇이 잘못되나 |
|---|---|---|
| 클릭은 메일을 연다 | 행을 클릭하면 메일 상세가 열린다. 확장이 클릭을 가로채 막지 않는다 | `mousedown` 단계에서 행을 감추거나 지우면 뒤따르는 `click` 이 그 행에 닿지 못해 메일이 열리지 않는다 |
| 강조된 행은 모두 같다 | 강조된 행은 전부 같은 방식으로 내려간다. 일부만 반응하는 일이 없다 | 띠 색에 따라 되고 안 되면 사용자가 규칙을 예측할 수 없다 |
| 연달아 열어도 모두 기록 | 메일을 연달아 열면 전부 기록된다 | 행마다 리스너를 달면 목록이 다시 그려질 때 사라져, 복원 전에 누른 메일이 기록되지 않는다 |
| 되돌리면 원래대로 | 내린 것을 되돌리면 띠와 배지와 숫자가 내리기 전과 같아진다 | 복원할 값을 남기지 않으면 배지가 빈 껍데기가 된다 |
| 접기는 회차를 넘기지 않는다 | 다시 분류하면 접혀 있던 행이 모두 보인다 | 접은 채 다시 분류하면 행이 숨은 채로 남는다 |
| 누른 행은 자리를 지킨다 | 방금 누른 행은 접기 상태여도 그 자리에 남는다 | 누른 행이 사라지면서 아래 행이 올라와, 다른 메일을 잘못 눌렀다고 느끼게 된다 |
| 표시는 그 메일의 것이다 | 목록이 행을 재사용해 다른 메일이 들어오면 누르기 전이라도 남은 표시를 걷는다. 분류하는 도중에 페이지를 넘겨도 판정은 그 메일에만 붙는다 | 다음 페이지의 엉뚱한 메일이 강조되고, 화면의 메일과 기록되는 메일이 어긋난다 |
| 접기는 돌아와도 이어진다 | 메일을 열었다 돌아와도 확인할 메일만 보는 상태가 이어진다. 확인할 메일이 없고 판정하지 않은 메일만 있는 목록에서는 풀린다 | 돌아올 때마다 풀리면 남은 것을 보려고 매번 다시 눌러야 하고, 안내 문구와 감춰진 행이 어긋난다 |
| 판정하지 않은 메일은 감추지 않는다 | 접은 상태여도 판정하지 않은 메일은 보인다 | 모르는 메일을 감추면 중요한 메일을 놓친다 |
| 비우기는 열린 화면에도 | 설정에서 판정이나 내려간 기록을 비우면 이미 열린 메일 탭도 따른다 | 탭이 한 번 읽어 둔 사본을 계속 써서, 비웠는데도 옛 판정과 내려간 표시가 나온다 |
| 맞추기는 멈춘다 | 가만히 두면 목록 맞추기가 스스로를 다시 부르지 않는다 | 메일함을 열어 둔 내내 돌아 CPU 를 쓴다 |
| 표시는 다시 그려도 살아남는다 | 메일 서비스가 행의 `className` 을 덮어써도 띠와 흐림이 유지된다 | 클래스로 스타일을 걸면 그때 표시가 조용히 사라져, 일부 행만 흐린 화면이 된다 |

## 판정

| 이름 | 깨지면 안 되는 것 | 깨지면 무엇이 잘못되나 |
|---|---|---|
| 입력은 모두 캐시 키에 | 판정에 넣는 값은 전부 캐시 키에 들어간다. 들어가지 않는 값은 입력에서 뺀다 | 읽음 여부처럼 나중에 바뀌는 값을 넣으면 판정이 처음 분류한 시점의 상태로 굳는다 |
| 같은 메일은 같은 판정 | 같은 발신자의 같은 형식 메일은 읽음 여부와 무관하게 같은 판정을 받는다 | 같은 종류의 메일이 이유 없이 갈린다 |
| 호출은 버튼에서만 | 분류하기를 누르지 않으면 외부 호출이 나가지 않는다. 자동 복원은 저장된 판정만 읽는다 | 비용이 사용자의 통제를 벗어난다 |
| 사용자 규칙이 앞선다 | 항상 확인과 항상 무시는 회신 불가 주소 판정보다 먼저 적용된다 | 자동 발송 주소가 모델에 닿기 전에 걸러져, 배포 실패나 결제 실패 알림을 살릴 방법이 없어진다 |
| 읽음 판정은 화면과 같다 | 확장이 읽었다고 보는 행과 메일 서비스가 읽음으로 그린 행이 같다 | 읽음 아이콘의 부재를 안 읽음으로 읽는 식의 오판이 대량으로 난다. 아이콘이 여러 갈래인 서비스가 있다 |

## 공개

| 이름 | 깨지면 안 되는 것 | 깨지면 무엇이 잘못되나 |
|---|---|---|
| 자격 증명은 나가지 않는다 | 저장소와 배포본에 API 키가 들어가지 않는다 | 클라이언트에 둔 키는 처음부터 비밀이 아니다. 설치한 사람이 소스를 그대로 볼 수 있다 |
| 개발 경위는 나가지 않는다 | 코드와 문서에 날짜와 건수로 된 개발 기록을 남기지 않는다 | 공개 저장소는 누구나 내려받아 분석한다. 규칙과 이유는 남기고, 언제 무슨 일이 있었는지는 남기지 않는다 |

## 검사 수단

| 불변식 | 무엇으로 검사하나 |
|---|---|
| 강조와 배지 일치, 숫자와 화면 일치, 섞임에는 이유가 있다 | `test/browser/audit.js` 를 메일함 콘솔에서 돌려 전수로 센다 |
| 표시는 다시 그려도 살아남는다 | 같은 진단이 상태 속성과 화면 표시를 대조한다 |
| 지움은 유지된다, 접기는 회차를 넘기지 않는다, 되돌리면 원래대로 | 조작 순서를 밟아 확인한다 |
| 클릭은 메일을 연다, 연달아 열어도 모두 기록 | 실제 브라우저의 `mousedown` 과 `click` 순서가 필요하다. `test/fixtures/inbox.html` 에서 진짜 클릭을 한다 |
| 강조된 행은 모두 같다 | 강조된 행을 전수로 훑어 상호작용 속성이 같은지 본다 |
| 입력은 모두 캐시 키에 | `tools/check.py` 가 판정 요청을 만드는 코드와 캐시 키를 대조한다 |
| 같은 메일은 같은 판정 | 같은 내용에 읽음 상태만 바꾼 두 행이 같은 키를 얻는지 본다 |
| 호출은 버튼에서만 | 네트워크 요청을 가로채, 버튼을 누르지 않은 구간에서 0건인지 본다 |
| 사용자 규칙이 앞선다 | `npm test` 의 발신자 규칙 시험이 순서와 충돌 해소를 고정한다 |
| 읽음 판정은 화면과 같다 | 프로파일의 판정과 **제목의 글자 굵기**를 전 행에서 대조한다. 아이콘이나 클래스 하나를 표본 몇 개로 확인하면 우연히 맞는 경우가 있다 |
| 누른 행은 자리를 지킨다 | 접은 상태에서 누르고, 눌린 행이 같은 위치에 같은 제목으로 남는지 본다 |
| 표시는 그 메일의 것이다, 접기는 돌아와도 이어진다, 판정하지 않은 메일은 감추지 않는다, 비우기는 열린 화면에도, 맞추기는 멈춘다 | `npm run scenario` 가 가짜 메일함에서 페이지 넘김 세 방식과 메일 열기 두 방식으로 흐름을 돌린다. 각 흐름은 고친 것을 하나씩 되돌린 사본에서 실패하는 것을 확인했다 |
| 자격 증명은 나가지 않는다, 개발 경위는 나가지 않는다 | `tools/check.py` 의 반출 게이트가 전 파일을 훑는다 |
| 문구는 사실을 넘지 않는다 | 자동 검사 밖이다. 문구를 고칠 때 사람이 본다 |

## 쓰는 법

새 기능을 붙였으면 이 목록을 위에서 아래로 한 번 훑는다. 검사가 통과해도 **문구는 사실을 넘지 않는다** 는 사람이 봐야 한다.

여기 없는 것이 깨지면 고치기 전에 이 목록에 먼저 적는다. 고친 뒤에 적으면 무엇을 지켜야 하는지가 아니라 어떻게 고쳤는지가 남는다.
